My assistant said 7919 × 6571 = 51,948,849. Why I stopped letting it do maths

I asked Atlas, my local AI assistant, what 7919 times 6571 is. It answered confidently: 51,948,849. It also said it had used its calculator. Both claims were false.

The correct result is 52,035,749, and no tool had been called. This post is about that failure, how I measured it, and the design rule I took from it.

The setup

Atlas is a personal assistant that runs on my own hardware. The language model is qwen2.5:7b on Ollama, and around it there are about fifty tools: calendar, email, weather, web search and, more recently, exact maths and physics built on SymPy and pint.

A 7-billion-parameter model fits on a home GPU and explains things well. What it doesn't do well is arithmetic.

Measuring it

I didn't trust my impression. I ran 12 science questions three times on the mini PC: 33 out of 36 correct, at about 8 seconds per answer. That sounds fine, but the failures were more interesting than the successes:

  • Sometimes it said nothing at all: no text, no tool call, just an empty message.
  • Sometimes it called the algebra tool without saying which operation to run.
  • It wrote LaTeX (\frac{1}{2}) even though the prompt forbade it, and read aloud by a voice assistant, that sounds terrible.

Then I ran a second round with calculations nobody can answer from memory. That exposed the worst failure: the model answered without the tool, claimed it had used it, and gave a made-up number. Exactly the 7919 × 6571 case.

Why it happens

A language model doesn't calculate. It predicts the most likely text. For "2 + 2", the most likely text is the right answer. For an eight-digit product, the most likely text is a number with the right shape and the wrong digits. And because it has seen thousands of answers that say "I used the calculator", it can write that sentence without having done it.

The problem isn't that it gets things wrong. It's that it gets them wrong with exactly the same confidence as when it gets them right.

The fix: code computes, the model explains

The rule Atlas follows now is simple: anything that must be exact is done by code; the model only explains it. It already worked this way for dates, because the model kept getting "next Friday" wrong. I extended it to numbers:

  1. Simple calculations are solved before the model sees them. "X times Y", "18.5% of N" or "the square root of N" are detected and computed by code, and the model receives the result to write the answer around.
  2. A clear calculation request answered without a tool is discarded. If I ask it to solve, differentiate or integrate and it answers without the tool, that answer is thrown away and retried once, this time requiring the tool. Explanations ("what is a derivative?") still don't need one.
  3. Numbers are checked on the way out. If a number in the answer matches a tool result but comes back with mangled thousands separators, it gets restored.
  4. Silence has a fallback. If the model returns nothing, it's retried once; if it's still silent, the user gets the result of the tool that already ran.
  5. LaTeX is converted to plain text in every answer, without touching Windows paths, amounts of money or code blocks.

The first point is the one that matters most. In simplified form, the idea looks like this:

import re
from decimal import Decimal

MUL = re.compile(r"(\d+(?:\.\d+)?)\s*(?:x|×|\*|times)\s*(\d+(?:\.\d+)?)", re.I)

def arithmetic_hint(question: str) -> str | None:
    """Compute simple products in code, so the model never has to."""
    m = MUL.search(question)
    if not m:
        return None
    a, b = (Decimal(s) for s in m.groups())
    return f"Exact result (computed by code): {a} × {b} = {a * b}"

arithmetic_hint("What is 7919 times 6571?")
# 'Exact result (computed by code): 7919 × 6571 = 52035749'

The hint goes into the model's context with the question. The model's job shrinks from "calculate and explain" to "explain this result", which a 7B model does well.

When I tried to be clever

One of my first fixes was to let the code guess the operation when the model forgot to specify it. The result: Atlas stated that the derivative of x·sin(x) is x·sin(x). Now, when information is missing, nothing gets guessed. It's the same lesson on a smaller scale: deterministic code only helps if it doesn't start imitating the model.

The general rule

If you build something with a small model, don't ask it to do everything. Split the work: the model understands the question and writes the answer, and code handles everything that has to be exact, such as dates, arithmetic, units and data. And test it with questions whose answers can't be guessed, because the easy ones hide exactly the failures that matter.
